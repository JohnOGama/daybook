# Uptime Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new Uptime space tool. Daybook's API checks each saved site every minute and shows it Up, Slow or Down, with 30 days of history, incidents and a live sidebar dot.

**Architecture:**
- An in-process scheduler in the NestJS API checks due sites through the same public-address guards as the job-posting fetcher. It stores each result and incident with Drizzle and pushes dot changes over the existing per-user socket.
- The Next.js app reads `GET /uptime/:spaceId` and `GET /uptime/monitors/:id` with React Query and renders the table, strip, tiles and drawer from the approved mockup.

**Tech Stack:** NestJS + Drizzle (Postgres, tests on PGlite) + zod; Next.js + React Query + shadcn/ui + Skullet; vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-uptime-design.md` (mockup: `.superpowers/brainstorm/2723-1795201871/content/uptime-tool.html`)

## Global Constraints

- Check every **60 s**; scheduler tick **15 s**; at most **5** checks at once; timeout **10 s**; slow above **2,000 ms**; one retry after **5 s** for a down result; at most **3** redirects; keep **30 days**; prune **hourly**.
- Up = final HTTP status **200–399**; a 3xx still unresolved after the third hop counts as an answer. The body is never read.
- `User-Agent: Daybook-Uptime/1.0`. http(s) only, no cookies; every connection's resolved address must pass `isPublicAddress`.
- At most **50** sites per space; URL at most **2,000** characters; name 1–100 characters, trimmed; Check now at most once every **10 s** per site (429).
- Bars: **48** half-hour buckets for the last 24 h, each the worst result in it (`down` > `slow` > `up`), `none` when empty. Uptime % counts up and slow as up; gaps are left out; `null` when there were no checks.
- Dot: `down` beats `slow` beats `up`; paused sites and sites never checked don't count; no countable site means `null`.
- API rules: `@UseGuards(AuthGuard)`, `@UserId()`, `parseOrThrow`, an explicit `@Inject(Token)` on every constructor parameter, `.ts` on relative imports, `SpaceAccessService` on every route, and `SpaceLockService.assertUnlocked` on reads. No access answers 404; a viewer on a write answers 403.
- Web rules: the `@/` alias; `PascalCaseComponent.tsx`, `useX.ts` and `kebab-case.ts` file names; `page.tsx` only renders the page component; Skullet for loading; colours green `status-done`, amber `signal`, red `destructive`, grey `muted-foreground`.
- **Don't commit.** The owner commits; each task ends by running its tests, and the work ends with a ready-to-paste commit message.

## Review Focus

1. **A redirect to a private address** (e.g. 302 → `http://127.0.0.1/`) must end Down with "Not a public address", never a request inside the network. Tested in Task 1.
2. **A site that streams a body forever** after 200 headers must still finish Up within the timeout, since the body is never read. Tested in Task 1.
3. **Repeated down checks** must keep one open incident, and the first up or slow check closes it. Tested in Task 3.
4. **A site deleted while its check is in flight** must not crash the scheduler: `record` for a missing site returns `null`. Tested in Task 3.
5. **A check exactly 24 h old** is outside the bars and the 24-hour uptime, and one 23 h 59 m old falls in the oldest bar. Tested in Task 3.

    - Inserts the check and updates the monitor's `status`, `lastCheckedAt`, `lastResponseMs`, `lastError` and `downSince` (set when going down, kept while down, cleared on up/slow).

  - `monitor(id: string, now?: Date): Promise<MonitorDetail>`

  - `dotStatus(spaceId: string): Promise<UptimeDot>`
