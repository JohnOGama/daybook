# Daybook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Daybook, a multi-user, day-based task manager with List and Calendar views, automatic carry-forward, subtasks, and email-code sign-up.

**Architecture:** A pnpm workspace with `apps/api` (NestJS, Drizzle, Better Auth, all business rules) and `apps/web` (Next.js, shadcn/ui, React Query). Next.js forwards `/api/*` to Nest so the browser sees one origin. Where a task appears is computed on read from its planned and finished days, so there is no nightly job.

**Tech Stack:** Node 22, pnpm 10, Next.js, NestJS 11, Tailwind CSS 4, shadcn/ui, TanStack React Query, Drizzle ORM, Neon Postgres (`pg` driver), Better Auth email OTP, Resend, Zod, Vitest, PGlite (tests only).

**Spec:** `docs/superpowers/specs/2026-11-09-daybook-design.md`. The approved look is `docs/superpowers/specs/daybook-screens.html`.

## Global Constraints

- Follow `CLAUDE.md` in full. Components are PascalCase ending in `Component`. Hooks are camelCase starting with `use`. Utilities, helpers and services are kebab-case, including Nest files (`tasks-service.ts`, not `tasks.service.ts`).
- A feature is `features/<name>/index.ts` plus `features/<name>/src/`, with React Query hooks in `features/<name>/hooks/` as `CLAUDE.md` shows. Other features import only through the barrel.
- `page.tsx` only renders a `*PageComponent`.
- Generated shadcn files keep their own names under `src/shared/components/ui/`.
- Comments only for context the code can't show.
- Days are `YYYY-MM-DD` strings everywhere. Compare them as strings. Never parse one with `new Date(day)`, which reads it as UTC and shifts a day west of Greenwich.
- Every task query is scoped by `userId`. Another user's task answers 404.
- Use the `pg` driver, not `neon-http`, because the spec requires transactions.
- All Nest constructor parameters use explicit `@Inject(Token)`, so tests run under Vitest without decorator metadata.
- API tests use PGlite and need no credentials. Only Task 9 needs Neon and Resend keys.
- Work on branch `build/daybook-v1`. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Someone signs up, leaves before entering the code, then comes back and signs in: they get a fresh code and reach the code screen. Test in Task 6.
2. A tab left open past midnight: on focus, it treats the new date as today and carried tasks appear. Test in Task 7.
3. The last two subtasks are ticked at almost the same moment: the parent ends finished. Test in Task 3.
4. A blank title, a 201-character title, or an impossible date such as `2026-02-31`: the API answers 400 and nothing is saved. Test in Task 5.
5. A day with no tasks: progress reads 0%, never `NaN%`. Test in Task 7.
