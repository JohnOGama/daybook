# Sharing Spaces and Folders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An owner shares a space or folder by email as Can edit or Can view. The recipient finds it under **Shared with me**, and the server enforces access on every route.

**Architecture:** A `space_shares` table is keyed by email. `SpaceAccessService.resolve*` turns "this user, this space or row, this need" into the owner's id, or throws 404 or 403. Controllers call it first and then pass `ownerId` to the existing, unchanged services, so everything a shared editor creates belongs to the owner. Whole-document saves gain a `version` column and answer 409 when the version is stale.

**Tech Stack:** NestJS (through tsx, explicit `@Inject`), Drizzle with Postgres and PGlite in tests, zod, Next.js, React Query, shadcn/ui, Skullet, vitest, supertest.

**Spec:** `docs/superpowers/specs/2026-11-15-sharing-design.md`

## Global Constraints

- Every constructor dependency has an explicit `@Inject(Token)`. Relative imports in `apps/api` end in `.ts`, and `apps/web` uses `@/`.
- Input is validated with `parseOrThrow(zodSchema, …)`. Services keep scoping every query to the `userId` they're given, which is now the owner's id.
- No access means **404** (a space you can't see looks like one that doesn't exist). Viewing allowed but editing needed means **403**. A stale whole-document save means **409** with the message `Changed by someone else`.
- Vault spaces are never shared or resolved for anyone but their owner. Trash and Vault routes stay owner-only.
- Emails are stored trimmed and lowercased. The share API never reveals whether an email has an account (no names in share responses, and the same answer for known and unknown emails).
- Web: shadcn/ui components, theme tokens only, lucide icons, Skullet for loading, optimistic mutations with `crypto.randomUUID()` ids, a toast and rollback on error. File naming follows CLAUDE.md.
- After a schema change, run `pnpm --filter api db:generate` so the PGlite tests see it.
- After code changes, run `graphify update .` from the repo root.

## Review Focus

1. **A body or array id that points at the owner's unshared space.** For example: `POST /tasks/bulk-delete` with one shared and one private task id, `PUT /tasks/order`, `POST /tasks/:id/copy` with a private target `spaceId`, a budget entry whose `accountId` belongs to another budget space, or `POST /fitness/foods/:id/servings` naming a private `spaceId`. Expect 404 and nothing changed. Tests: Tasks 5, 7 and 8.
2. **A space inside a shared folder that is itself a Vault, or was deleted, or whose folder was deleted.** Expect it to be absent from `GET /spaces` and 404 on resolve. Tests: Task 2.
3. **A share made before the recipient has an account.** Once they sign up with that email, it appears with no extra step. Mixed-case or padded emails still match. Test: Task 2.
4. **A viewer calling an AI route or a read-only-looking POST** (`POST /notebook-pages/:id/versions` checkpoint, `POST /jobs/:id/match`, `POST /budget/ai/insights`). Expect 403. Tests: Tasks 6, 7 and 9.
5. **An old page or diagram open in a second tab after a save elsewhere.** Its next save is refused with 409 and the web shows Reload. A title-only rename never 409s. Tests: Tasks 10 and 12.

### Task 2: `SpaceAccessService`

**Files:**
- Create: `apps/api/src/features/spaces/src/space-access-service.ts`

- Modify: `apps/api/src/features/spaces/src/spaces-module.ts` (provide and export it)

**Interfaces:**
- Consumes: Task 1.
- Produces:
  ```ts
  export type Access = 'owner' | 'edit' | 'view';
  export type Need = 'view' | 'edit';
  export type Resolved = { ownerId: string; access: Access; spaceId: string };
  type SpaceScoped = PgTable & { id: AnyPgColumn; spaceId: AnyPgColumn; userId: AnyPgColumn };

  resolve(userId: string, spaceId: string, need: Need): Promise<Resolved>
  resolveRow(userId: string, table: SpaceScoped, rowId: string, need: Need): Promise<Resolved>
  resolveRows(userId: string, table: SpaceScoped, rowIds: string[], need: Need): Promise<Resolved>
  sharedWith(userId: string): Promise<{ row: SpaceRow; access: 'edit' | 'view'; ownerName: string }[]>
  ```

Rules:

- **`resolve`.**
  - If the space is missing or soft-deleted, it throws 404.
  - If `space.userId === userId`, it returns `owner`.
  - If the space is a Vault, it throws 404.
  - Otherwise it walks the `parentId` chain to the root. Any deleted ancestor means 404.
  - It reads the user's email from `user` and finds `spaceShares` rows with `spaceId IN chain AND email = lower(email)`. If there are none, it throws 404. The best role wins (`edit` beats `view`). If `need === 'edit'` and the role is `view`, it throws 403.
- **`resolveRow`.** It reads `{ spaceId }` from `table` where `id = rowId` and calls `resolve`. A missing row, or a row with a null `spaceId` (built-in fitness foods and exercises), throws 404.
- **`resolveRows`.** It resolves every distinct `spaceId` among the rows. A missing row throws 404, and so do rows spanning more than one owner. It returns the first `Resolved`.
- **`sharedWith`.**
  - It finds every share for the user's email. For each share it loads the owner's non-deleted spaces in memory and returns the root and all its descendants.
  - It skips Vault spaces, and any space with a deleted ancestor.
  - It drops the user's own spaces and removes duplicates, keeping the best role.
  - A returned row whose parent isn't in the returned set has its `parentId` set to `null`.
  - `ownerName` comes from `user.name`.
