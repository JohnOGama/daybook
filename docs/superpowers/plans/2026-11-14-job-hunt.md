# Job Hunt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Job hunt" space tool: add jobs from a link (AI reads the posting) or by hand, move them through Saved → Applied → Interviewing → Offer / Not accepted with a dated trail, see waiting nudges and overview tiles, and get an AI match against the owner's pasted CV.

**Architecture:** A new `jobs` value of `space_tool`, two tables (`job_profiles`, `jobs` with a jsonb `events` trail) and a NestJS `JobsModule` that stores and checks ownership. The server fetches posting pages itself behind an address guard and asks Gemini through `BudgetAiService`. Everything derived (waiting days, tiles, counts, search, sort) is computed in the browser in `jobs-math.ts`; the web holds one React Query object `['jobs', spaceId]` patched optimistically.

**Tech Stack:** NestJS + Drizzle + PGlite tests (API), Next.js + React Query + shadcn/ui + Skullet + vitest/RTL (web), `@google/genai` (already installed), Node stdlib `node:http`/`node:https`/`node:dns`/`node:net` for fetching.

**Spec:** `docs/superpowers/specs/2026-11-14-job-hunt-design.md`. The approved mockup is `.superpowers/brainstorm/1144-1794599015/content/job-hunt.html` (local only); match its layout.

## Global Constraints

- Follow `CLAUDE.md`: feature folders with `src/` and `index.ts`; `PascalCaseComponent.tsx`, `useX.ts`, kebab-case utilities; `page.tsx` only renders the page component; `.ts` extensions on relative API imports and `@Inject(Token)` on every constructor dependency.
- Don't commit. The owner commits; end each task by writing a ready-to-paste commit message in your report.
- Statuses are exactly `saved`, `applied`, `interviewing`, `offer`, `rejected`; `rejected` is shown as "Not accepted".
- Status dot colours: Saved `status-todo`, Applied `status-progress`, Interviewing `status-hold`, Offer `status-done`, Not accepted `muted-foreground`. Match ring and "no reply" line use `signal`. Logos are the company initial on `bg-muted`. No palette classes.
- Limits: `role`, `company` 1 to 200; `url` http(s) up to 2,000; `location` up to 120; `salary` up to 80; `employmentType` up to 40; `description` up to 30,000; `notes` up to 5,000; `events` up to 200; `nextStepNote` up to 120; `cvText` up to 20,000; match `summary` up to 300, `skillsHave` / `skillsMissing` up to 12 items of up to 40 characters, `pct` integer 0 to 100.
- Nudge at 7 days waiting; "close it?" from 30 days; "Waiting on a reply" detail counts 14 days or more.
- Page fetch: http/https only, non-public addresses refused at connect time on every hop, at most 3 redirects, 10 s timeout, 2 MB cap, `text/html` or `text/plain` only, no cookies; page text capped at 30,000 characters, JSON-LD at 10,000.
- AI is sent only one posting's text and JSON-LD (`readPosting`) or the CV plus one job's role, company and description (`matchJob`). Never notes, statuses or other jobs.
- "Today" is the browser's `useToday()`; never the server clock for days.
- Skullet for every loading state (sample data from `sample-jobs.ts`); no spinners.
- Labels to copy verbatim: "Job hunt", "Add job", "Add manually", "Add your CV" / "Your CV", "Reading the posting…", "Saved", "Applied", "Interviewing", "Offer", "Not accepted", "Mark applied", "Follow up", "Recheck", "AI estimate", "CV changed since this match", "Tailor my CV", "Coming next", "N days, no reply", "close it?".

## Review Focus

1. **A link the site won't show without a login** (LinkedIn, Indeed, a 403/999 reply) should open the manual form with the link filled in and the reason shown, not an error toast. Tests: Task 2 Step 1 (`login` reason for 999 and for a redirect to `/login`), Task 5 Step 1 (fallback dialog).
2. **The same link pasted twice** should select the existing job and say "Already added", not create a duplicate. Test: Task 5 Step 1, with `normalizeLink` tested in Task 4.
3. **Back-dated or out-of-order events** (a status recorded for an earlier day after a later one) must not break "Applied" or waiting days; both read days, never array order. Test: Task 4 Step 1.
4. **A job with no description or no CV** must not call the AI for a match; the match route answers 400 and the panel explains instead of offering Recheck. Tests: Task 3 Step 1, Task 6 Step 1.
5. **A posting longer than the limits** (huge page, long AI description) is cut to size, never refused or stored over the limit. Tests: Task 2 Step 1 (30,000-character cap), Task 2 Step 4 (description trimmed).
