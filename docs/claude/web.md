# Web data flow, UI and loading

## Web data flow

- The active space comes from the `?space=` param through `useActiveSpace`. Task queries are keyed `['tasks', spaceId, from, to, today]`; the other roots are `['spaces']`, `['space-groups']` (the sidebar's groups, like "Spaces" and "Work"), `['trash']`, `['pages', spaceId]` (Notebook pages, Book chapters and skills, which autosave through `usePageAutosave` instead of rolling back), `['page-versions', pageId]` (a page's history, read only while its panel is open), `['vault']`, `['vault-items', spaceId]`, `['budget', spaceId]` (a Budget's accounts, categories and entries in one object), `['fitness', spaceId]` (profile, weigh-ins, meal plans and workout templates), `['fitness-days', spaceId, from, to]` (food logs, workouts and water for a range of days), `['fitness-foods', spaceId, …]` (food search, recent and own foods), `['fitness-exercises', spaceId]`, `['jobs', spaceId]` (the CV and every job in one object), `['diagram', spaceId]` (whether the diagram AI is on; the text and positions come from the live document), `['space-lock', spaceId]` (whether a locked space is unlocked in this browser), `['space-shares', spaceId]` (who a space is shared with, read only while the Share dialog is open), `['pipelines', spaceId]` (each job's newest run with its expected stages, plus the 30 newest runs), `['pipeline-run', runId]` (one run for the drawer, read only while it is open) `['pipeline-key', spaceId]` (when the key was made and last used, owner only), `['uptime', spaceId]` (an Uptime space's sites with their 24-hour bars and the tiles, refetched every minute while open), `['uptime-monitor', id]` (one site's uptime, response times and incidents, read only while its drawer is open), `['focus', spaceId, from, to]` (a Focus space's timer lengths and its sessions for the last 7 days; the running timer itself lives in `localStorage`, see `docs/claude/focus.md`), `['connected-apps']` (the AI apps the person has approved, in Settings) and `['oauth-client', clientId]` (the app's name on the OAuth consent page).
- The Vault encrypts in the browser (`features/vault/src/vault-crypto.ts`). Its query cache holds ciphertext only. The key and decrypted items stay in component state, never in the cache, storage, the URL, toasts or logs.
- Mutations are optimistic: the client generates IDs with `crypto.randomUUID()`, patches the cache, and on error restores the snapshot and shows a toast. A successful change does not refetch.
- Task mutations are created once by `TaskMutationsProviderComponent`; rows read them with `useTaskMutations`, and memoised rows rely on `task-cache.ts` keeping unchanged tasks the same object.
- Because of that, server rules are mirrored in `features/tasks/src/task-cache.ts` and `features/spaces/src/space-cache.ts`. A behaviour change in a service usually needs the matching cache change.

## UI

shadcn/ui (new-york style) on Radix with Tailwind CSS v4, with generated components in `apps/web/src/shared/components/ui`. Also `lucide-react` icons, `sonner` toasts and `@dnd-kit` for reordering.

The app is monochrome, light by default with a dark theme (`docs/theme.md`). `next-themes` (`ProvidersComponent`) puts `dark` on `<html>`, chosen in Settings → Appearance and kept per browser; light tokens are on `:root` and dark ones on `.dark` in `globals.css`. Anything that can't read a CSS variable (React Flow's `colorMode`) reads `useTheme().resolvedTheme`. Black (white in dark) does the work: buttons and selected states. The orange `--ring` is only the keyboard focus ring, and inputs have no border or focus style. Buttons and other clickable roles get a pointer cursor from the base layer in `globals.css`. Text is Geist, and `h1`–`h3` outside page content use the rounded display font (`font-display`). Use the theme tokens in `globals.css` rather than Tailwind palette classes, and keep colour for `destructive` (errors and delete actions), the dark yellow `signal` accent (high priority and progress), the `status-*` accents (task status, and job status in Job hunt) and `money-in` / `money-out` (signed amounts in Budget, through `moneyTone`). The one other exception is brand logos (`features/budget/src/brand-icons.ts`), which keep their brand colours; their shapes come from Simple Icons (CC0), a few presets use logo images saved in `apps/web/public/brands`, and the rest are brand-coloured initials. Floating surfaces get their border and shadow (none in light) and dialog overlays their dimming from the `data-slot` rules in `globals.css`; the sidebar (`nav[aria-label="Main"]`) swaps `--muted` and `--accent` to white in light so its rows and inputs stand out on the grey.

Someone with no space yet gets `WelcomeComponent` from `SpaceGateComponent` and no sidebar (`AppShellComponent`, `FirstRunBarComponent` with Settings and Sign out). Trash, Settings and Assistant still show the sidebar. "Browse tools" opens `CreateSpaceFormComponent` in a dialog; the form lists the tools before the title everywhere.

## Skeleton loading

Use Skullet (`skullet/react`) for every loading state, with no spinners, "Loading…" text or blank screens. Disabled submit buttons during a form action are not loading states.

- **Data views:** render the real component from sample data inside `<Skeleton loading={isPending} label="…">`, so the skeleton matches the final layout. See `ListPageComponent` and `sample-tasks.ts`.
- **Before any content exists** (session checks, Suspense fallbacks): use the `SkeletonBox` layouts `AppSkeletonComponent`, `PageSkeletonComponent` or `AuthCardSkeletonComponent`.
- **Tests:** sample text stays in the DOM but hidden, so query by role rather than text.
- **Large live views:** Skullet keeps measuring the content inside `<Skeleton>` after loading; for big, constantly changing views (the database diagram) render the loaded content outside it.
- **Colours:** `SkulletProvider` gets no `mode`; the skeleton colours are `--skullet-base` and `--skullet-highlight` per theme in `globals.css`.
- **Debugging:** add `?skullet-debug` to a URL to outline each skeleton and show layout shifts.
- **The `id` prop:** it remembers shapes across visits. If you start using it, call `forgetShapes()` on sign-out.

## Landing page

- `/` is the public landing page (`features/landing`, `LandingPageComponent`), light by default like the rest of the app. Signed-in people stay on it and see a Dashboard link (to `/list`) in place of Sign in. Its copy and the repo link live in `landing-content.ts`; the tool previews are real screenshots in `public/landing/` taken from a demo account with made-up data, never from a real one.
